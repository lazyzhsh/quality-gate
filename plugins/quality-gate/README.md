# Quality Gate

Quality Gate turns "software is deliverable" into a traceable proof chain: Claim → Evidence → Gate → Risk → Exception. The kernel is agent-platform-agnostic (pure Node 20+ standard library, no npm dependencies, no network at run time); this plugin is the first delivery adapter and the same CLI runs standalone in CI. The current 37 gate kinds cover L0-L5: the **semantic track** (terminology plus eight semantic-* gates, a deterministic OWL subset — equivalence/union/subproperty/inverse/transitivity —, kernel-native SHACL Core components with an optional pyshacl engine union, multilingual terms, the pinned FIBO catalog); the **principles/practice track** (F2P/P2P false-fix guard, payment-data consistency — zero-sum ledger, append-only, reconciliation, DLQ retention, kernel-recomputed audit chain —, api-authz/credential scans, timeout/retry budget conservation, breaker-path drills, topology semantics, rerun determinism); the **four alignment-protection tracks (all closed)** (task-intent register with drift reconciliation, convention alignment with ADR binding, symbol grounding with API declaration faces, trace-continuity with replay baselines); **verdict & governance** (canary verdict protocol, approved-exception windows, summary-layer evidence strength); and **trust convergence** (kernel-parsed raw TAP/JUnit/observation records — declared and verified —, baseline content binding, observation-side source fingerprints). Per-version capability history lives in `docs/release/` at the marketplace root; proof boundaries live in `docs/GATE-SPEC-v1.23.md` and `docs/RTM.md`.

After every run the CLI prints a graded human-readable report to stderr — PASS prints a one-line brief (with the evidence-strength line when measurable signals exist); anything else prints the full per-gate Markdown table with reasons, a suggestion column and run duration — while stdout remains the canonical JSON report for tooling. The Stop hook block reason carries the same summary, and the skill/command/SessionStart prompts require the agent to paste the graded report into its reply as Markdown body (never inside a code fence). Each evidence entry in the report records its gate `kind` and `level`.

Requires Node.js 20+, no packages or network access required. Use the quality-gate command/skill or `node bin/qgate.mjs <project-root> close`. Configure `.quality-gate.json` via the `/quality-gate-init` guided dialogue (`node bin/qgate.mjs templates [lite|pro|max]` lists the tiered preset library — 7 templates + 6 add-ons; `node bin/qgate.mjs init <root> <answers.json>` assembles and writes the validated config) or adapt an example by hand; upgrade existing configs through `/quality-gate-update` (`inspect`/`update`). `node bin/qgate.mjs report <project-root> [runId]` re-renders an archived run's human report without re-running gates. SessionStart provides context, dependency-install hints and the latest archived baseline status; Stop runs gates and blocks on non-PASS (v1.24: only deterministic file checks can reuse verdicts with identical before/after/current content snapshots; runners and time-dependent checks rerun; opt-in `stop.blockMode:"new-only"` downgrades pre-existing failures with untouched declared inputs to a warning; ungated projects and adapter-internal errors no longer block). Restart sessions after enabling or updating. Non-Node projects (pytest/surefire/gradle) can wire the unit gate through the reference adapters in `adapters/` (native tool output parsed and recounted by the kernel).

L1 executes configured argv as the current user; review project configuration like build scripts. It can modify files or access the network if configured commands do so. L0 checks assumption register state. Reports are written under project .quality-gate/runs (Stop hook included since v1.14, falling back to ZCODE_PLUGIN_DATA when the project directory is not writable); stdout/stderr may contain secrets. No automatic uploads. CLI exit codes: 0 PASS, 1 FAIL, 2 ERROR/SKIP. Use CI for enforcement; Stop retries have a client limit. Proposed exceptions block; approved exceptions render WAIVED within their approval window (approval is a declared field, not signature-verified, and never waives a failing gate). Ontology CLI exposes a pinned FIBO subset, fibo-skeleton, and replaceable local-catalog providers.

Run tests: `node --test tests/*.test.mjs`. Deployment: add the containing marketplace as a local source in ZCode Settings → Plugin management → Discover; install, enable, start a new session (upgrade: re-sync the marketplace snapshot first, then use the update button on the plugin row). Full Chinese guide, staged plan, specification and validation log are in the marketplace root.

L2 persistence Gate: see examples/persistence-demo (Python 3.10+ stdlib). It invokes a real local HTTP API, independently reads committed SQLite data, and compares every configured field. Since v1.10.0 the `before`/`after` database snapshots are mandatory by default (`requireSnapshots` defaults to true; the after snapshot must come from an independent session per ADR-0013) and opting out requires an explicit `"requireSnapshots": false`. Runner input/output JSON carries a unique runId. Never use response echoes as database evidence. All scenarios use temporary test storage.

L2 ontology-map Gate: see examples/fibo-demo. It checks that configured IRIs exist in the bundled, SHA256-verified FIBO `master_2026Q1` Agreements/Contracts subset (52 classes with subClassOf/disjointWith edges), or in a configured local catalog. This proves term presence only; it does not validate business mapping or perform OWL reasoning. Details and upstream attribution are in the marketplace root `docs/FIBO-PROVIDER.md`.

The six-domain example at examples/six-domain-demo combines gates across L0–L5 and requires every domain at close/release. examples/examples.manifest.json is the single source of truth for all 46 examples (smoke stages included; the delivery build runs them from this manifest). Full contracts and limits are in the marketplace root `docs/GATE-SPEC-v1.23.md`. Proposed exceptions are recorded and block; approved ones render WAIVED within their window without ever waiving a failing gate.
