# ADR-0012：双轨迭代与文档治理约定

- 状态：已接受（v1.3/v1.4 并行会话实践固化为约定；2026-09-25 文档重组补全结构）
- 日期：2026-09-25

## 背景

用户以**两个并行会话在同一主树迭代**的方式推进（语义轨道与原则/实践轨道），版本号顺延冲突（原 v1.4 规划因语义轨道先发 1.4.0 改编号 v1.5）。同时 docs/ 随版本累积出 35 份文档，出现"README 停在 1.3、讨论记录未完成项停在 v1.1"等失真。

## 决策

1. **迭代模式**：允许双轨并行会话共树迭代，轨间正交（语义 vs 原则/实践）；版本号以先发布者为准，后发轨道顺延编号并在 PLAN 声明。
2. **文档分层治理**（docs/ 重组后的结构）：
   - 产品层：`PRD.md`、`RTM.md`、`adr/`——回答"是什么、为什么、追到哪"；
   - 规范层：`GATE-SPEC-v<版>.md`（活规范，随版本改名）、`CONFIG-GUIDE.md`、`PERSISTENCE-GATE.md`、`FIBO-PROVIDER.md`；
   - 状态层：`PLAN.md`（下一版规划+历史基线）；实现状态索引为产品层 `RTM.md`（其前身"设计覆盖台账"于 2026-09-25 归档至 history/）；
   - 历史层：`release/`（各版发行说明 RELEASE-*，按版本递增——2026-09-25 应用户要求自 history/ 拆分，便于追溯发行历史）与 `history/`（LIVE-ACCEPTANCE-*、ITERATION-*、旧版 SPEC、VALIDATION——均只增不改，按当时语境理解）；
   - 上下文层：`context/`（原始设计、RESEARCH-* 调研输入——研究输入自 2026-09-25 起由独立研究层并入；均非实施承诺）。
3. **链接纪律**：活文档（根 README/AGENTS/PROJECT-HANDOFF、规范、状态、PRD/RTM/ADR）引用历史文档时指向 `history/`，移动/改名时全量修复相对链接（已建立脚本化校验）；历史文档内部互链保持同目录，指向活文档的链接同样修复。
4. 根目录只保留 AGENTS.md、PROJECT-HANDOFF.md、README.md 三个入口。

## 后果

- 正面：入口收敛；"当前状态"类失真问题有了结构性解法（活文档唯一、历史不可变）。
- 负面：每次移动历史文件需跑链接修复；并行会话的未跟踪文件归属仍需人工约定（本 ADR 不解决）。

## 备选方案

单轨串行（拒绝：用户明确选择并行提效）；文档按日期扁平堆放（拒绝：本次重组前的失真即后果）。
