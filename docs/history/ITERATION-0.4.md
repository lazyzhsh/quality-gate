# v0.4 计划：需求与验收条件追踪 Gate

目标：新增 L0 `traceability` Gate，让显式需求和验收条件关联到项目内的实现文件及本次运行的测试 Gate 证据。它检查追踪链是否完整、文件是否真实存在且留在项目根内、关联的 Gate 是否在同一阶段实际 PASS。它不从自然语言自动推断覆盖，也不宣称测试内部断言一定验证了验收条件。

分步交付和自测：

1. 固定 RTM JSON 格式：每条 requirement 至少一项 acceptanceCriterion；每项声明非空 codeFiles 和 testGateIds。建立兼容 Gate Spec 的结果与风险边界。
2. 先写失败用例：缺代码文件、路径逃逸、缺关联 Gate、关联 Gate FAIL/SKIP、重复 ID、空验收条件。再实现检查，且与配置顺序无关。
3. 加真实小项目示例，运行 PASS→FAIL→修复；所有旧 Gate 回归。
4. 官方结构校验、分发 ZIP 解包回归和 CLI 退出码验收；记录证据。完成后继续下一阶段，最后统一做 ZCode 客户端验收。

当前设计决策：RTM 只提供显式可追踪性证据。要证明每个 AC 被测试执行，应由后续结构化测试结果或用例专属 Gate 加强；本轮不以“文件存在”冒充完整需求覆盖率。
