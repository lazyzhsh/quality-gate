# Gate Spec 1.16（配置 schemaVersion 0.2）

本版为**统一语言治理版（DDD 式术语统一+协议键迁移，34 kinds 与判定语义零变化）**：配置与 run 报告 schemaVersion 0.1→0.2——`gates[].domain`→`gates[].level`、`requiredLevels`→`requiredLevels`、update changes `addAddOns`→`addOns`（旧键 fail-closed 拒绝并指名迁移，先例 v1.8/v1.9；归档 run 重渲染经读兼容垫片继续可用；观察协议与 transcript schema 键零改名，schemaVersion 保持 0.1）；报告域字段 `domainCoverage`→`levelCoverage`、`evidence[].domain`→`level`；随版发布修复：update changes 白名单补 `ontology`（文档已承诺）、打包含集排除 `.zcode/`。词汇规范见 [GLOSSARY](../GLOSSARY.md)。前一版（v1.15）主线零破坏（34 kinds 不变）：声明 expected 的基线证据从"ref 存在性核验"升级为"内容绑定+两源一致"——git 型 baselineSource 可选 `file`+`contentSha256`（内核 `git show <ref>:<file>` 取内容 Buffer 原样 sha256 内容比对，不符/不在 ref 树中 ERROR fail-closed，一致计证据力信号**"基线内容核验"**）；behavior 观察记录顶层可选 `baseline` 块（与观察 baselineSource 同形同值，两源不一致/观察缺失 ERROR 指名），门禁级可选 `requireBaselineTranscript`（缺块 FAIL 指名）；engineering unit 观察可选 `baselineRawOutput:{format:tap|junit, file}`——内核解析基线实现的原始测试输出、逐用例重算基线状态与自报 `baselineStatus` 交叉核验（不符/缺用例/重名 ERROR），核验一致后 F2P/P2P 基线侧判定取内核重算值，门禁级可选 `requireBaselineRawOutput`。这是 B1（v1.11 TAP/JUnit）→ C3（v1.13 transcript）→ C2（v1.15 基线侧）三轮同构收尾链的最后一环——内核核验内容绑定+两源一致，仍不执行基线（不可信 runner 伪造执行记录的残余风险与 B1/C3 同类，如实声明）。v1.15 随版发布：`qgate inspect` 建议块（附加门禁库 `suggest` 元数据 × `git status --porcelain -uall` 未提交变更面——变更影响驱动的 add-on 推荐，建议性输出不代写配置）；consumer-usage 观察层深化（Pact 请求 body 字段路径 → 字段级使用面；扫描器 python/go/java 常见形状）。其余判定规则延续 v1.12/v1.13/v1.15。内核与 Agent 无关；ZCode Hook、Command、Skill 触发同一个 CLI。项目 `.quality-gate.json` 配置 `claims`、`gates`、`risks`、`exceptions`、可选 `requiredLevels` 和 `ontology`。报告按执行阶段写入 `.quality-gate/runs/<uuid>.json`。`PASS` 才可放行；`FAIL`、`ERROR`、`SKIP` 退出码分别为 1、2、2。最多 32 个 Gate，同阶段配置的超时总预算上限 40 秒。

| L4 | `resilience` | 故障场景、最大恢复时间、最终状态、必需信号；可选 `requiredTransitions`（熔断全路径演练：runner 回报 `transitions` 序列须与期望一致且 `breakerEventsLogged:true`）与 `maxAgeDays`（演练观察须带 `observedAt`，过期即 FAIL） | 故障、恢复耗时、状态、log/metric/trace/alert、状态机序列与跳变日志、证据过期 |
| L4 | `budget` | 文件式纯内核算术（无 runner）：`hops` 每跳 timeoutMs×(retries+1) 之和须 ≤ 调用方 `budgets` 预算（调用方未声明即违规）；`retryPolicies` 预算 ≤20%、jitterMode∈full/equal/decorrelated、backoff cap≥base | 逐跳尝试次数、需求合计 vs 预算、missingCallerBudget/budgetExceeded/retryBudgetExceeded 违规 |
| L4 | `topology` | 拓扑语义（R1–R4，纯内核判定声明文件，无 runner）：R1 关键服务与关键依赖的 `distinct(failureDomain)>=2`（replicaDetails 逐副本 region/zone/host+role；无域信息须显式 domainVerification:"unavailable" 降级并进报告降级行）；R2 副本阈值按 stateModel 分型（stateless≥2/consensus≥3 且奇数/standby≥3/byzantine≥3f+1）；R3 一阶最小割集（节点单点+单实例依赖边，与"无单点"严格等价；二阶仅计数）；R4 role 对称或 leader 语义（primary/leader 或 standby 须 transientLeadership+leaderLeaseSec） | 逐规则 findings 指名服务与依赖、minCutOrder1 清单与计数、minCutOrder2Count、mustSurvive 集合、降级登记 |
| L4 | `rerun` | 重跑确定性证据（R6，文件式纯内核校验，无 runner）：`jobs` 每任务 ≥2 次同 seed `runs`（sha256 输出哈希）+ `idempotencyKeyStrategy`；可选 `doubleEntry` 复式恒等式；runs<2、异 seed、算法未声明即 ERROR | 逐任务 runs 数/seed/确定性结论、outputDivergence（哈希不一致）、unbalancedDoubleEntry（借贷不等）违规 |
| L5 | `configuration` | 多环境文件、允许差异路径（支持 `*` 段通配）、秘密引用 | 缺键、类型冲突、未声明差异、明文秘密（脱敏） |
| L5 | `documentation` | 代码/API/用户/运维制品版本与主题；制品 path 由内核核验存在且非空 | 各制品缺失主题、版本偏差、制品文件缺失/为空 |
| L5 | `debt` | 技术债登记，owner/影响/偿还/期限；空登记须显式顶层 `"none": true`（裸空数组 FAIL）；resolved 项可选 evidence `{file}`/`{gateId}` 引用核验 | 高严重度和逾期未结项阻断、空登记未显式声明、引用未通过 |

`assumptions` 空登记须显式顶层 `"none": true`（与非空条目矛盾即 FAIL）；可要求来源/证据/影响/风险/处理（`requireProvenance`）；其 `source`/`evidence` 字段支持结构化引用：`{file}` 经存在性与防逃逸核验，`{gateId}` 须为同次 PASS 的门禁证据，未知门禁或畸形引用即 ERROR，纯文本保持登记不核验；该门禁在关联门禁之后评估。`traceability` 可要求 normal/boundary/negative/exception/state-transition AC 类型（逐需求 `requiredTypes`，或门禁级默认集 `defaultRequiredTypes` 适用于未自带的需求）；需求可选 `prdRef:{file,section}`（file 存在性+防逃逸核验，可选 `requirePrdRefs:true` 强制每条需求绑定 PRD）；其 `testGateIds` 可引用除 `traceability` 之外任意 kind 的门禁（元门禁在 RTM 之后评估，不能充当同次测试证据）；可选 `coverage: {argv, timeoutMs}` runner按 AC 核验链接代码文件是否被执行，未覆盖即 FAIL，runner 协议与其他门禁一致（同次 runId、结构化观察）；`persistence` 可要求 API 前后数据库快照并输出字段 delta；可选 `expectedRecordCount`（默认 1）：0 断言必须不落库（此时期望 HTTP 状态允许非 2xx），>1 为批量——runner 须回 `records` 数组且与 `requireSnapshots` 互斥（1.10.0 E3 起 `requireSnapshots` 默认 true，批量必须显式置 false），逐条按 expected 模板核对。已有 `command`、`ontology-map`、`semantic-profile`、`behavior`、`metrics` 保持兼容。`metrics` 为纯阈值判定（1..20 个 `{min?,max?}`，证据纪律已于 1.8.0 随 L4.2 裁剪）；灰度判定协议（R5）以拓扑声明 `canaryAnalysis` + runner 指标表达（inconclusive 不计 PASS、guardrail 矛盾、SRM 作废，模式见 CONFIG-GUIDE 架构适应度模式库）。全部示例在 `plugins/quality-gate/examples/`，逐任务状态及证明边界见 [RTM](../RTM.md)。

所有 runner 由项目显式配置为参数数组 `argv`，通过 stdin 接收当次 `runId`，stdout 输出相同 `runId` 的 JSON 观察。缺失、过期、格式错误、超时或非零退出均不会 PASS。`$NODE` 使用插件当前 Node 可执行文件。`traceability` 的 coverage runner 与 `change-scope` 的 contentCheck runner 遵循同一协议；contentCheck 收到 baseRef/baseCommit 与逐文件变更类型，finding 是否接受由配置的 `acceptedFindings` 决定，runner 无权自判放行。change-scope 的 R/C 变更同时报告源路径（`R-source`/`C-source` 类型）。runner 在项目根运行，拥有当前用户权限；正式项目应在隔离的测试环境配置其依赖与目标。示例安全扫描、SVG 对比、SQLite 结构观察与故障演练只证明该演示场景。

报告含 configSha256 与逐门禁证据（`releasePackage`/`priorRuns` 跨运行哈希链已于 1.8.0 裁剪）。证据时效已由 `maxAgeDays`/`acknowledgedOntology` 按门禁覆盖（声明式豁免 `acceptedFindings.expiresAt` 同理过期自动恢复阻断）。提议的 Exception 登记即阻断；已审批（`status:"approved"` + `approvedBy`/`approvedAt`）且在 `expiresAt` 有效期内 → 报告呈现 **WAIVED**（单独列示、计入例外台账、不改变任何门禁判定——豁免从不把 FAIL 门禁变成 PASS）；过期或未生效自动回退阻断。审批为声明字段，无签名防伪造。FIBO 固定 Agreements/Contracts 两模块 52 个类（含 subClassOf/disjointWith 边，随包 vendored、逐源 SHA 核验、运行不联网，手动升级工作流见 docs/FIBO-PROVIDER.md），并可通过 local-catalog 替换；IRI 对齐、RDFS 子集闭包与有限 JSON profile 不等于完整 OWL/SHACL 推理。semantic-profile 规则与 SHACL Core 词汇对齐（逐条 violation 标注等价约束组件），但内核不是 SHACL 引擎。映射维护可采用提案-确认-pin 工作流：LLM/匹配工具提案写入 `ontology-proposals.json`（含 confidence），人工接受后 pin 进 mappings，`qgate.mjs proposals` 审计 accepted-not-pinned 漂移；门禁不读取提案文件，confidence 不构成证据。

## 引导初始化（v1.7 新增；v1.7.1 扩展生命周期；v1.8 附加门禁目录随裁剪调整）

项目缺 `.quality-gate.json` 时的配置创建走确定性协议（[ADR-0014](../adr/ADR-0014-guided-onboarding.md)）：档位化模板库（lite ⊂ pro ⊂ max，7 模板 + 6 附加门禁，`lib/templates.mjs` 静态数据）→ answers 契约（`templateId` + 可选 `addOns/disable/substitutions/requiredLevels`，未知字段或目标即拒绝）→ `qgate.mjs init` 装配（禁用级联清理 risks/exceptions/孤儿 claims → 合并附加门禁 → 替换 → **占位符残留即拒绝并定位路径** → 内核 `validate()`）→ 写入。写入仅发生在 CLI 层且对已有配置需显式 `--force`；ZCode 会话内由 `/quality-gate-init` 引导对话问询（agent 不代写配置）。SessionStart 缺配置注入引导指向；内核缺配置报错为可行动文案。模板/附加门禁清单与 answers 字段表见 [CONFIG-GUIDE 引导初始化与模板库](../CONFIG-GUIDE.md)。模板产出的配置仍受本规范全部判定规则约束：骨架协议在 runner 与登记文件补齐前按 fail-closed 报 FAIL/ERROR，不得以禁用门禁或创建例外换取放行。

配置生命周期分权（v1.7.1，[ADR-0015](../adr/ADR-0015-config-lifecycle.md)）：**重初始化**＝`qgate.mjs leftovers` 确定性列出残留（根目录已知登记文件名 + 旧配置引用 + `.quality-gate/` 目录），经用户确认后 `init --fresh` 删除（不可恢复；装配失败不删）并全新引导；**升级/增量调整**＝`qgate.mjs inspect`（有效性/预算/溯源与模板漂移/可用附加门禁/登记文件存在性；v1.15 起附**变更影响驱动的建议块**——附加门禁库 `suggest` 元数据 × `git status --porcelain -uall` 未提交变更面路径匹配，建议性输出不代写配置，非 git 仓库如实 unavailable）+ `qgate.mjs update`（changes 契约增量应用 + `migrateRegistries` 迁移），ZCode 会话内经 `/quality-gate-update` 引导。init 写入顶层溯源 `template:{id,generatedAt}`（内核校验形状；update 刷新 generatedAt）。登记文件默认集中 `.quality-gate/registries/`（可提交），运行数据仍在 `.quality-gate/runs/`（gitignore 仅忽略 runs/）。

引导契约收尾（v1.7.2，实机验收反馈）：answers/changes 新增 `ontology`（fibo-skeleton/local-catalog/fibo-pinned 严格键集；随包目录 sha256 由 `qgate.mjs templates` 的 `ontologyHint` 发布，six-domain 默认 skeleton 仅占位、L2 语义门禁运行 ERROR 属 fail-closed）与 metrics `thresholds` 替换（自有指标名 1..20 个、min/max 与 validateMetrics 同构）；init/update 写盘后做登记文件门禁引用预检（`testGateIds`/`affectsGateIds` 引用不存在门禁即 `preflightGateRefs` 警告，只读不阻断）——配置全程仍只由 init/update 写入，无 post-init 手改通道。

## 摘要输出

每次运行后，CLI 向 stderr 输出**分级**人读报告（v1.7.4 起；stdout 仍是完整 JSON 报告，供 CI 与打包脚本消费，判定语义不变）：

- **PASS（整体通过）**：一行 brief——状态/阶段/通过计数/总耗时（报告级 startedAt→finishedAt）/run id、层级覆盖行、证据路径与全表重渲染提示；不再附带全表，避免对话内刷屏；存在弱来源声明（embedded 基线/static 观察/declared 来源/拓扑域信息显式降级）时附"证据降级"行（PASS 也显示）；存在可汇聚的实测信号时附**"证据力"行**（v1.10.1 R12）——只读聚合 **PASS 门禁**的证据信号（git 基线核验/来源指纹核验/同 seed 双次运行一致/持久化前后快照/**原始输出解析**[v1.11 B1 unit rawOutput；v1.13 起含 behavior/journey rawTranscript；v1.15 起含 unit baselineRawOutput]/**基线内容核验**[v1.15：git show 内容内容比对一致]）与定量信号（测试计数、覆盖率、变异分数、性质与行为用例数），等级由实测推导：`核验级`（存在内核可独立核验的证据信号）/`声明级`（仅 runner 自报数值，形状经内核校验）/`降级`（存在证据降级声明，优先级最高），无信号不显示该行（不虚报）；数值全部取自各门禁 details 实测。
- **非 PASS**：全量 Markdown 表——总体状态、阶段、通过/跳过计数、耗时、层级覆盖、未满足必需域、逐门禁的 `kind`/`level`/状态、按 kind 提取的失败原因（超限截断并给出剩余数）与**建议列**（FAIL→按原因修复后重跑；ERROR→检查 runner/配置输入；SKIP→不在本阶段执行），末行给出证据路径与放行提示。Stop Hook 非 PASS 时的阻断 reason 使用同一全量摘要。

`qgate.mjs report <project-root> [runId]`（缺省取 `.quality-gate/runs/` 最新一次；runId 接受**唯一前缀**，≥4 字符、歧义即 fail-closed 列出候选）不重跑门禁、直接重渲染归档运行的全量报告，并前置标注归档时间戳与「非当前状态」守卫行，供会话内引用历史证据。全表另含每门禁**耗时列**（evidence 的 startedAt→finishedAt）；展示路径按当前工作目录相对化（仅显示层），重跑/全表命令中的 qgate.mjs 自 v1.14 起按绝对路径渲染（任意 cwd 复制即用）。Stop Hook 自 v1.14 起：归档结论与当前配置一致且其后输入无 mtime 变更时直接复用不重跑（freshness fail-safe，无法判定即重跑）；可选 `stop.blockMode:new-only` 将会话前既有且声明输入未变的 FAIL 降级为非阻断警告（ERROR、未声明 inputs、配置漂移仍阻断；只影响 Hook 呈现，不改判定与退出码——配置语义见 CONFIG-GUIDE「Stop Hook 行为」）；项目无配置与 adapter 自身错误不再阻断。提示词层（SKILL/命令/SessionStart）要求 agent 把分级报告以 **Markdown 正文**贴进回复（不得包代码围栏，否则加粗与表格不渲染）、正文说明控制在一两句：PASS 贴 brief 行，非 PASS 贴全表并随修复循环更新。报告中每条 Gate Evidence 均含 `kind` 与 `level` 字段。摘要是展示层，不改变任何判定语义。

## 外部依赖提示

内核仅依赖 Node 20+；`git` 为 change-scope 所需，`python`/`python3`/`py` 为登记的示例 runner 命令，`chrome`/`msedge` 为 visual 浏览器参考 runner 的候选外部工具（v1.13 起，`QGATE_BROWSER` 可显式指定路径）。运行前内核按登记表预检（仅 `--version`），报告含 `dependencies`（required/missing/hint/url）；SessionStart 在新项目注入缺失提示与安装链接，摘要输出"缺少外部依赖"行，注册表命令 ENOENT 时追加安装指引。项目自定义工具不做预检。
