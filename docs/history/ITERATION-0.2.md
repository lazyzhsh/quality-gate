# v0.2：持久化数据逐字段检查

前置：v0.1 已在 ZCode 3.14.3.7762 完成真实 Stop Hook 失败与恢复闭环。

本轮边界：新增一个 L2 persistence Gate，以真实 HTTP→SQLite demo 验证，不扩展业务本体推理。本轮通过后再进入 FIBO 固定版本导入。

小步验收：
1. 明确 runner 协议和失败判定，先编写负例测试。
2. 内核执行配置的 runner，把唯一 runId 经 stdin 传入；读取结构化观察结果，由内核比较预期字段。runner 不决定 PASS。
3. 独立 Python 标准库 demo：临时 SQLite 数据库、loopback HTTP 服务、POST 创建记录、独立连接查询；退出时关闭服务并清理临时数据。
4. 检查正常持久化、HTTP 错误、漏写、错写、字段遗漏、重复记录、类型变化、关联 ID 错误、非法输出与超时。
5. 执行原有回归、真实 CLI 与 Hook 子进程验收、官方目录校验、ZIP 解包验收。记录局限与下一步。

信任边界：runner 是项目集成代码，必须审查。内核不可能仅靠 runner 自报信息证明它真的访问了数据库；demo 以真实调用演示该接入契约。v0.2 不默认访问已有业务数据库，运行新 demo 不改变已验收 demo 或已安装 v0.1。
