# 分阶段计划与验收

目标:Agent 无关内核,ZCode 为首个适配器;Quality Domain 与执行阶段分离;每增量本地可出真实正反例,小步节奏"分析→确认→正反例→实现→全量回归→证据"。历史轮次的规划细节由 [docs/release/](release/) 各版发行说明与 [docs/history/](history/) 承接,本文只保留逐版一行完成记录,不再展开已完成规划。

## 当前状态（2026-10-01，v1.24.0）

1.24.0 为首次 GitHub 早期开源发行：615 回归全过、0 SKIP；37 kinds/46 示例。审查中的 11 组问题已修复，支持范围和发布验证见 [OPEN-SOURCE-STATUS](OPEN-SOURCE-STATUS.md) 与 [RELEASE-1.24.0](release/RELEASE-1.24.0.md)。

完整回归实测 77.5 秒；过去 47 秒记录不能作为永久解决性能问题的依据。根 close 仅做 G-CONVENTIONS，完整回归在 CLI pr/release（180 秒 command）执行。Stop 配置执行预算 50 秒，为宿主 55 秒期限保留核验与落盘余量；不靠重启或单次达标结算期限问题。

## 下一步与未完成项

1. 在一个真实业务项目接入测试/契约/数据库与独立观察，量化错误放行、错误阻断、接入成本、Stop 耗时和修复轮数。
2. 增强逐 Claim 证明范围、混合来源显示、AC→真实测试用例绑定，避免总体 PASS 被理解为所有意图已证明。
3. 按 RTM 7 条部分需求逐项补真实工具和验收证据；最终支持面需明确，尚未实现效果不靠改状态结算。
4. 新版本 ZCode 实机验证单独记录；CLI/模拟与以前版本记录不能代替。
5. 以上完成后再评估 v2.0、transcript 默认政策和第二 adapter。

范围决定保留：R13 拓扑推导/编排、签名、仓库自有 CI、1.8.0 裁剪项和双人核准不因开源发布恢复。
